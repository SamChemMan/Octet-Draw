# H-bond donors, H-bond acceptors and rings in Properties (PR #152)

Prof. Schramm's PR #152 (4022e45), ported onto release-1.1.3 at 9ca16e2 on `item/c-ss152`. Sam: "do it, get it
to WORK". The commit is cherry-picked with his authorship. Only `THIRD_PARTY.md` conflicted (the ssign row that
1.1.3 added next to the RDKit row); both rows are kept.

## ChemDraw

ChemDraw has no such rows. Its Analysis window has Formula to Elemental Analysis, and its Chemical Properties window
has Boiling Point to pKa, tPSA, logP, MR and CLogP (`notes/chemdraw26-inventory.md`, Chemical Properties window).
So these rows go past ChemDraw. Since 25.5 ChemDraw works out logP and MR with RDKit, so RDKit's counts are the
closest standard to ChemDraw's own source.

## Definitions

- H-bond donors and acceptors: RDKit's `NumHBD` and `NumHBA` (`Code/GraphMol/Descriptors/Lipinski.cpp`; NumHBA
  version 2.0.2, changed on 29 January 2026 so an aromatic N with three neighbours is no acceptor, in 2026.03 and
  later). These are RDKit's `Descriptors.NumHDonors` and `NumHAcceptors`. They are not Lipinski's own counts
  (RDKit's `NHOHCount`: every N-H and O-H hydrogen; `NOCount`: every N and O). Each row's method in
  the report says so, with acetamide as the example (1 and 1 here, 2 and 2 by Lipinski).
- Rings: the size of the smallest set of smallest rings, bonds - atoms + separate parts. Cubane gives 5 (RDKit's
  symmetrised set gives 6); the row's method says so.

## What it must do, and how each is tested

1. The panel shows H-bond donors, H-bond acceptors and Rings after tPSA, with whole numbers. Test:
   `proprows.check.ts` (row order and values, from his commit).
2. The values are right for aspirin, caffeine, paracetamol, glucose, morpholine, pyridine, indole, urea, ethanol and
   benzoic acid, by RDKit's NumHBD and NumHBA. Test: `props.check.ts` on hand-built graphs (his table has 8 of the
   10; glucose and urea added), and `molecule.check.ts` end to end, from SMILES as Indigo reads them, through
   `structures` and the panel's `propertyValues` with Octet's calculators.
3. Copy (a click on a value), Add to drawing (`propertyRuns`, live values) and Copy report (`propertyReport`) include
   the three rows the same as other rows. Test: `proprows.check.ts` (report lines from his commit; Add to drawing runs
   and a live value that follows its structure, added).
4. More than one structure, and a reaction: one value per structure, separated by semicolons, as every other row.
   Test: `molecule.check.ts` with two structures and with a reaction from SMILES.
5. Drawn H atoms count as their neighbour's hydrogens. Test: `props.check.ts` (ethanol with drawn H, his commit).
6. No speed cost on pointer moves: the counts are worked out once per structure with the other calculators
   (`calculated`, kept in a WeakMap), only while the panel is open. Timing: `properties()` on the check molecules
   before and after.

## Design

His code as it is: three counters in `src/props.ts` on the calculators' existing context, three rows in
`src/proprows.ts`. The panel, Copy, Add to drawing, live values and the report read `PROPERTY_ROWS`, so they need no
change. No new setting, no file format change (a live value stores row keys; Octet 1.1.2 skips a key it does not
know).

The MCP's `add_values` takes any `PROPERTY_ROWS` key, so it takes `hbd`, `hba` and `rings` with no new op. Its
description still lists the old keys: for 1.2, add the three there.
