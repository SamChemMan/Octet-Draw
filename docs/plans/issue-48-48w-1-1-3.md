# Issue 48: a paste from Octet into LibreOffice opens in Octet (Windows, and Calc)

Branch `item/b-48w`, from `release-1.1.3` f06d1b49. For release 1.1.3 (Friday 20 November 2026). Finishes two lines of
decision 0025's "Not done":

- Windows: a structure pasted from Octet into LibreOffice does not open in Octet.
- Calc: a structure pasted from Octet does not open in Octet, on any system.

LibreOffice is not installed on this Mac and must not be. Everything is proved from LibreOffice's public source, Rust
tests and Octet's checks. The real runs are steps in `docs/testing/libreoffice-manual.md`.

## 1. What it must do

1. Copy on Windows puts a clipboard type that LibreOffice Writer, Impress, Draw and Calc take before Octet's bitmap
   and EMF, and that keeps the drawing's CDXML in the picture LibreOffice stores. A double-click on the pasted picture
   then opens it in Octet, and the context menu has Edit in Octet Draw.
2. Word, PowerPoint, Excel and ChemDraw get the same as before: the same types, in the same order, with the same
   bytes, with the Office object on or off. The EMF keeps its EMF+ records.
3. A paste from Octet into Calc opens in Octet, on every system where LibreOffice can read it.
4. The extension (`tools/libreoffice/octet_draw.py`) recognises the pasted picture in Calc as in Writer.
5. Copy is no slower than in 1.1.3 so far (the hot-path rule).
6. The manual checklist gets steps for each new fact.

## 2. What LibreOffice does (its public source, master on 19 November 2026)

Read, not copied: `sot/source/base/formats.cxx`, `sot/source/base/exchange.cxx`, `vcl/win/dtrans/ftransl.cxx`,
`vcl/osx/DataFlavorMapping.cxx`, `vcl/source/gdi/TypeSerializer.cxx`, `vcl/source/gdi/gfxlink.cxx`,
`include/vcl/gfxlink.hxx`, `tools/source/stream/vcompat.cxx`, `vcl/source/filter/graphicfilter.cxx`,
`sd/source/ui/view/sdview3.cxx`, `sd/source/ui/view/sdview2.cxx`, `sc/source/ui/view/viewfun3.cxx`,
`sc/source/ui/view/viewfun5.cxx`, `sw/source/uibase/dochdl/swdtflvr.cxx`, `sfx2/source/view/frame2.cxx`.

- Paste takes the first format in the program's own table that the clipboard has (`GetTransferableAction_Impl`).
  The clipboard's order does not count.
- Writer (the free-area copy table): SVXB comes before every other picture (PDF, PNG, BITMAP, GDIMETAFILE) and before
  Windows' OLE objects. Today on Windows it takes BITMAP (Octet's `CF_DIB`).
- Calc (`ScViewFunc::PasteFromSystem`, the Calc free-area copy table): SVXB comes before OLE objects, GDIMETAFILE and
  BITMAP. There is no PDF in the table. `PasteDataFormat` reads SVXB with `TypeSerializer::readGraphic` and inserts the
  graphic.
- Impress and Draw (`View::InsertData`, called with no format by `DoPaste`): PDF first, then OLE objects only when
  there is no GDIMETAFILE, then SVXB, then GDIMETAFILE. On Windows Octet's copy has no PDF, so they take SVXB.
- SVXB is `application/x-openoffice-svxb;windows_formatname="SVXB (StarView Bitmap/Animation)"`. On Windows LibreOffice
  registers the name in `windows_formatname`, so the format is `SVXB (StarView Bitmap/Animation)`, the name Octet
  already reads (`SVXB_WINDOWS`). On Linux the format is the whole MIME string, which Octet already reads (`SVXB`).
- On the Mac, the table that maps pasteboard types to LibreOffice's formats spells it `svbx`. A pasteboard type
  `…svbx…` becomes a format LibreOffice does not know, and `…svxb…` maps only inside the LibreOffice that wrote it
  (`maOfficeOnlyTypes`). So LibreOffice for the Mac reads no SVXB from another program.
- `readGraphic`: "NAT5", an empty version header, then the link (`readGfxLink`): a version header, its type (2 bytes),
  the file's size (4), a user number (4), and from version 2 the size and map mode, then the file.
  `GfxLink::LoadNative` reads the file with the importer for its type: 12 is `NativePdf`, read by LibreOffice's PDF
  reader, which keeps the bytes (`GraphicFilter::readPDF`). The graphic is the same as a pasted PDF's: MIME type
  `application/pdf`, kept as `0fdp` plus the PDF, which the extension reads (`picture_of`).
- A WMF or EMF link (type 6) is read as a WMF graphic, which the extension does not know (`0fmw`). So the SVXB holds
  the PDF.
- Calc's views pass mouse clicks to `XMouseClickHandler` like the other programs (`SfxFrameWindow_Impl::PreNotify`),
  and a selected picture on a sheet is a `GraphicObjectShape` in the selection. The extension already handles
  `SpreadsheetDocument` (`DOCUMENTS`, `selected_picture`, Insert). Calc's only gap is the paste.

## 3. How

- `clipboard.rs`, `types()`: on Windows and Linux, after Octet's JSON (last, so every earlier type keeps its place and
  bytes), put LibreOffice's own copy of a picture holding the PDF (`svxb_of`): "NAT5", an empty header, a version 1
  link header (10 bytes of fields), type 12, the PDF's size, user 0, then the PDF. Version 1 has no size or map mode:
  LibreOffice takes them from the PDF, as for a pasted PDF.
- Linux already makes the PDF. Windows makes it from the tree it has read, after the EMF, on the thread that makes the
  EMF beside the bitmap. The EMF and the PDF each take a small part of the bitmap's time.
- No SVXB when the picture is switched off in Settings, when Octet cannot make the PDF (a font it cannot embed), or
  when it would be over paste's 64 MB limit for one type.
- With the Office object on, the SVXB goes through the OLE clipboard like the other formats (`clip_object`).
- The Mac is not changed (section 6).
- The extension needs no code change. Its comments say where pictures come from.

## 6. Cut, and why

- Calc on the Mac. LibreOffice for the Mac reads no SVXB from another program (section 2, the `svbx` spelling), and
  Calc takes no PDF. Nothing Octet puts on the pasteboard reaches Calc as a PDF. In Calc on the Mac a structure goes in
  by Insert > Octet Drawing, or as a copy of a Writer, Impress or Draw picture. A LibreOffice fix (the table's
  spelling) would make an SVXB from Octet work there; that is LibreOffice's change to make.
- A real LibreOffice run on Windows and Linux: none here. The checklist has the steps.

## 7. What's New (for Sam; not written into `src/releases.ts`)

- When you copy a structure in Octet and paste it into LibreOffice Writer, Impress, Draw or Calc on Windows, you can
  double-click it to edit it in Octet.
- When you paste a structure from Octet into LibreOffice Calc on Linux, you can double-click it to edit it in Octet.
