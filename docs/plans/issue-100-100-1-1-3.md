# Title and author on Home, and Last changed by (#100, 1.1.3)

Branch `item/b-100`, from `release-1.1.3` (f06d1b49), for Octet Draw 1.1.3 (Friday 20 November 2026). Plan written
19 November 2026.

Title, Author, Keywords and Comment are on release (Settings > Document > Properties, `src/experiment.ts`
PROPERTIES). The reporter's two asks that are left:

1. See the title and the author without opening the drawing.
2. Know who changed the drawing last.

## What it must do

A1. Home's Recent tiles show the drawing's Title in place of the file name when it has one. The line under the name
shows the time, then the Author ("2 hours ago · Zoë Ångström"), so a long name is cut and the time is not. With no title the tile shows the file name, as
now. The tile's tooltip still shows the file's place, so the file name is never lost.

A2. A drawing in a folder on Home shows the same, from the recent list when the drawing is on it, else from what
Octet kept in the folder when the drawing was last opened or saved.

A3. The Experiments list shows the Author beside the file name under each title (the title is there already).

A4. Home reads nothing new from disk. The title and author come in `recent_list` with the picture, kept in
`recent.json` when the drawing is opened or saved. Home is no slower.

B1. Each save (Save, Save As, Save Copy As) sets "Last changed by" to the computer user's name (`user_name` in
`main.rs`: the full name on the Mac and Linux, the login name on Windows). With no name (a browser preview), it
stays as it was. Only a drawing with an Author gets the name. A save of a drawing with no Author takes Last changed
by out, and no file written from it holds a name (CDXML, CDX and `.oct`, Octet's own part of each included, and so
a PDF's CDXML and the clipboard's CDX). Every new drawing gets the user as its Author (`authored`), so the default
is the name in the file; clearing Author in Settings > Document > Properties keeps every name out (review, 19 Nov).
Sam may prefer a Settings > Files switch instead; this is the smaller of the two.
The rescue Save As in the error screen (`App.tsx`) and Update to Word (`officeUpdate`) do not set it: the first
writes what was saved, the second goes into a Word document, which is not a save of the drawing.

B2. Settings > Document > Properties shows Last changed by as plain text, read-only, when the drawing has it and has
an Author.

B3. Last changed by goes in CDXML as the document's `ModificationUserName`, in CDX as tag 0x0004 on the document,
and in `.oct` (CDXML inside). It comes back from each. A PDF export carries it in the CDXML it holds.

B4. A save that changes Last changed by does not leave the drawing marked as changed, and does not add an undo
step: it amends the current step.

B5. Last changed by does not go into a copy of part of a drawing, nor into an own template.

## How

- `experiment.ts`: `CHANGED_BY` ("Last changed by", an annotation keyword, as the comment is), `changedBy(annotations)`
  (none when there is no Author) and `stamped(m, name)` (the drawing with that name, or without one when there is no
  Author, or the same drawing when nothing changes). `oct.ts` writes Octet's own part of `.oct` and CDX through
  `stamped(m, "")`. It is not in
  PROPERTIES, so Settings' fields and the AI tools' `properties` cannot set it.
- `cdxml.ts`: the writer puts the first Last changed by annotation on the root as `ModificationUserName` and leaves it
  out of the annotations, as it does the comment; with no Author it writes neither. The reader turns a root `ModificationUserName` into that
  annotation, cleaned to one line of 200 characters at most (when the annotations are full it is counted as a lost
  annotation).
- `cdxtags.ts`: tag 0x0004 reads and writes as a string ("str"), so CDX and CDXML agree.
- `Editor.tsx`: `save` and `saveCopy` write `stamped(doc, systemName)`; `save` amends the drawing with it. The effect
  that sends the picture to `recent_thumb` sends the title and author too.
- `recent.rs`: `Recent` has `title` and `author` (optional). `recent_thumb` takes them, each checked (one line, 200
  characters at most, no C0 control characters; C1 stays, as `oneLine` keeps it). A value from `recent.json` that fails the check is dropped, the
  record stays.
- `projects.ts`: a folder's drawing keeps `title` and `author` (optional, checked as above when read);
  `homeLibrary.ts` updates them when a drawing in a folder is opened or saved, as it does its picture.
- `Home.tsx`: the tiles and the Experiments list as A1 to A3. `editor.css`: the line under a tile's name is cut with
  an ellipsis.
- `SettingsWindow.tsx`: the read-only row. `mcp.ts`: `read` gives `changed_by` (AI is off in 1.1.3; the code only
  runs with AI on).

## ChemDraw cross-check (from Octet's notes only)

Sources: the public CDX specification (Document object), `~/octet-research/notes/binary-tag-table.json`, the ChemDraw
22.2 help page Document Properties, `chemdraw26-inventory.md` and the corpus of Sam's ChemDraw files.

- The CDX document has CreationUserName (0x0001), CreationDate (0x0002), CreationProgram (0x0003),
  ModificationUserName (0x0004), ModificationDate (0x0005), ModificationProgram (0x0006), Name (0x0008) and Comment
  (0x0009). The specification calls ModificationUserName "the name of the last modifier (program user's name)". This
  is the same thing as Last changed by, so Octet uses it.
- None of the 76 ChemDraw files in Sam's corpus has CreationUserName or ModificationUserName in CDXML. ChemDraw writes
  CreationProgram only. Whether ChemDraw keeps ModificationUserName when it saves an Octet file again is not checked
  (no ChemDraw run in this job). If it drops it, Octet shows no Last changed by for that file, which is true: Octet
  did not save it.
- File > Document Annotations (keyword and content pairs) holds Octet's Title, Author and Keywords already, so
  ChemDraw shows them.
- File > Document Properties (typed rows with rules, up to 100, in a DocumentProperties object, 0x8030) is ChemDraw's
  other metadata. It has no fixed Author or Last changed by. Octet does not have it (cut, below).
- ChemDraw has no list of recent files with titles or authors: its File > Open Recent shows file names. Octet's Home
  tiles go further than ChemDraw here.

## Stress cases

1. A drawing with no title: the tile shows the file name, no dot, as before.
2. A title and no author: the title, and the time alone under it.
3. An author and no title: the file name, and "Author · time".
4. A title of 200 characters, an author of 200: both cut with an ellipsis on the tile; the tooltip shows the place.
5. Emoji and accents in the title and author, through recent.json and back.
6. A recent.json edited by hand: a title with a line feed, 10,000 characters, a number in place of a string. The
   value is dropped, the tile and its picture stay; the list still reads.
7. `recent_thumb` called with a title of a million characters from a hostile page: the title is dropped, the picture
   is still kept.
8. A drawing renamed to a new title and saved: the tile shows the new title the next time Home shows.
9. The title removed in Settings and the drawing saved: the tile shows the file name again.
10. A drawing in a folder that is not on the recent list: the tile shows the title Octet kept in the folder.
11. home.json from 1.1.2 (no title or author on a drawing): reads as before.
12. home.json with a hostile title on a drawing (an object, a line feed, too long): dropped, the drawing stays.
13. Save with the same user: Last changed by is unchanged and the drawing is the same object (no amend, no change).
14. Save on another computer with another name: Last changed by changes; ⌘Z after it does not undo the save's name
    alone (it is in the same step as the last change).
15. Save As to CDX: tag 0x0004 holds the name; Octet reads it back.
16. A CDX from another program with 0x0004 as a CDXString with style runs: Octet reads its text.
17. A CDXML with a 1,000,000-character ModificationUserName: cut to 200 characters on one line, the drawing opens.
18. A CDXML with `ModificationUserName` holding a line feed and a tab: one line.
19. A ChemDraw file with an annotation keyword "Last changed by" and no root attribute: read as Last changed by (the
    keyword is Octet's own); with both, the root's wins and the annotation stays.
20. Copy part of a drawing: no ModificationUserName in the copy.
21. An own template made from an experiment page: no Last changed by.
22. Settings with Last changed by set: one read-only row; Settings' search finds it by "modified", "changed", "user".
23. Settings fields Title, Author, Keywords, Comment changed: Last changed by stays.
24. The AI tools' `properties` cannot set Last changed by.
25. A new drawing: no Last changed by until it is saved.
26. Recovery copies (autosave) do not set it: only a save by the user does.
27. Experiments list: author shown after the file name; a drawing moved or deleted still says so.

## Cut, and why

- A PDF document information entry for Last changed by. The PDF information dictionary has no such entry
  (ISO 32000-1, 14.3.3 lists Title, Author, Subject, Keywords, Creator, Producer and two dates). The exported PDF
  holds the CDXML, which has it.
- ChemDraw's File > Document Properties (typed rows with rules). It is a feature of its own, not this issue.
- CreationUserName and the creation and modification dates. Not asked for; the file's own date shows on Home.
- Last changed by on the Home tile itself. The tile shows the Author, as the reporter asked; Last changed by is in
  Settings. A third line on a tile would crowd it.
- A check in ChemDraw that it keeps ModificationUserName. This job may not run ChemDraw. Sam can open an Octet CDXML
  in ChemDraw 22.2, save it, and look for `ModificationUserName` in the file.
