# NMReDATA for Octet Draw 1.1.3 (issue 111)

Stefan Schramm's issue 111: an assignment made in Octet goes on in Mnova, and Mnova's comes back. A file both sides
read is enough. Sam approved the full plan (`docs/plans/issue-111-nmredata.md` on `item/111-nmredata`, dab3e755) for
1.2 and then for 1.1.3, which ships with AI off on Friday 20 November 2026. This plan is that one cut to what 1.1.3
can ship, built on `item/b-111` from `release-1.1.3` at f06d1b49.

## What it must do

1. File > Export… > NMReDATA writes one SD record for each structure (selection or whole drawing). The Save dialog
   suggests `<drawing>.nmredata.sdf`.
2. Edit > Copy As > NMReDATA puts the same text on the clipboard. No key, as ChemDraw has no such item.
3. Each record carries the measured multiplets linked to its atoms, for each nucleus with a linked measured spectrum,
   and Octet's predicted shifts (¹H, ¹³C, ¹⁹F, ³¹P) for the other nuclei, with the Spectrum panel's frequency, solvent
   and decoupling.
4. Predicted shifts are marked four ways: `Predicted=` and `Spectrum_Location=none` in the 1D tag, `;predicted` after
   each assignment line, and a `Comment=` in `NMREDATA_ID` with the nmrshiftdb2 notice.
5. After Export or Copy As the notice says which nuclei are predicted ("Saved X.nmredata.sdf. The ¹H and ¹³C shifts
   are predicted.") and how many linked multiplets it left out (a ¹H multiplet linked to a C=O).
6. File > Import, File > Open, Finder and Explorer, a drop on Home or on a drawing, and Paste read an NMReDATA file.
   Each nucleus becomes a measured peak list, each signal a multiplet with the file's shift, multiplicity, J, count
   and range, linked to the atoms its label names. The Spectrum panel, the shifts beside atoms, the text line and Add
   to drawing show them.
7. Opened as a drawing: the panel opens on the first spectrum. Into a drawing: the structure lands beside it,
   selected, and each peak list takes the place of the drawing's spectrum of that nucleus. One undo step.
8. Octet's own predicted 1D tags are not read back as measured. What a file has that Octet cannot hold is named in
   one notice ("Octet left out 3 2D correlations.").
9. The format exactly as published (nmredata.org, tag format 1.1, 1D attributes, end of line, parser notes), checked
   by a strict reader in the check. Every file hostile.

## How

- `src/nmredata.ts` holds the format: `writeNmredata` (records), `readNmredata` (the hostile reader) and
  `nmredataDrawing` (a read file as structures, links and peak lists).
- Atom numbers: the molfile is Indigo's from `expandWithOrigins(part)`. The writer checks the molfile's elements
  against the expanded atoms and writes no assignment when they differ. Prediction runs on the bonded expansion (as
  the panel does) and maps to molfile atoms by drawn atom, element and place among those. ¹H: H atoms by number,
  implicit hydrogens as `H<n>`. Labels are atom numbers (`5`, `H5`, `H5a` and `H5b` for two signals on one atom), as
  Mnova writes them.
- `measured.ts`: `Group.given` keeps a file's shift, name, J values, count and range. `analyse` uses it, and a group
  with `given` is never taken for the solvent. `.oct`, CDXML and CDX keep it (`givenOf` checks it as hostile). An NMR
  peak list's sticks go on a 0.001 ppm grid in ChemDraw's object (0.01 for ¹³C ranges) and come back as sticks.
- Editor: `nmredataOf`, `exportPart` (NMReDATA branch), `copyNmredata`, `insertNmredata`; `readFile` opens one as a
  drawing; `importFile`, `dropFiles` and both paste paths call `insertNmredata`. `place` returns the drawing it set.
- Rust: `FORMATS` gets `("nmredata", "NMReDATA", ["sdf", "sd"])`, `default_extension` names it `.nmredata.sdf`
  (Export and `--convert --to nmredata`), and Copy As gets `copy_nmredata`. Export writes the text as it writes SDF.
- MCP: `nmredata` in `FILE_FORMATS` (quiet), so `read` gives Export's text; the headless host writes it too. The MCP
  is off in 1.1.3 (AI false), so this adds nothing a user sees there.

## Stress list

Each is in `src/nmredata.check.ts` unless it says otherwise.

1. Empty file, tags with no molfile, molfile cut short: "It has no structures."
2. Cut inside an item: lines before it read; the cut last line left out and named.
3. Atoms `0`, `-3`, `999`, `H0`, `H99`, `1.5`, `x`: each left out and counted.
4. Odd numbers (`7.6-`, `7.2--`, `NaN`, `1e400`, `0x1F`, 20,000): left out. `-5.1--4.9` and `7.6-7.2` are ranges.
   `777.777` is an unknown shift.
5. LF, CRLF, CR, mixed, BOM, tabs and trailing spaces, version 1.0, a number split by a bare line feed, a 1.1 item
   with no backslashes, fields with no space: the same spectra and links.
6. 300,000 characters read in under 300 ms (43 ms here); one over refused in under 50 ms; 2,000 signals kept.
7. Quoted labels with commas and parentheses, an unclosed quote, a label over 64 characters, a label used twice,
   ambiguous `(a, b)` links (unlinked, counted), 500 open brackets (read flat).
8. 10,000 data items: the first 256 read. Two assignment items: the first used. 101 records: 100 read.
9. Levels 1 and 3: `Interchangeable=` named; `Equivalent=` read as plain labels.
10. `NMREDATA_J`, DEPT (`Sequence=`), a second list for one nucleus, a selective 1D, 2D tags: named.
11. Two records: one peak list for each nucleus with both structures' multiplets.
12. 20 isotopes: the first 16 kept, 4 named.
13. Explicit H atoms (the format's ethanol example), implicit (Mnova), diastereotopic `H5a`/`H5b` written back the
    same; a ¹H link on a C=O left out of the export and counted.
14. An aromatic H at 7.26 in CDCl₃ stays the compound's.
15. Round trips: Octet's file read back gives the same links; predicted lists are not read; `.oct`, CDXML and CDX keep
    `given` and the sticks.
16. Copy into another drawing: no links, so export predicts.
17. Labels (OMe) numbered after the drawn atoms; cis SMILES (a backslash) not written; paclitaxel written in under
    1 s (89 ms here) and passes the strict reader.
18. The menu item, command, palette name, Export entry, Rust format and every way in are wired (source checks).

## Cut, and why

- MCP `add_file` and `drawings new` bringing NMReDATA spectra, the `export` tool's pick list and an MCP check: the
  MCP is off in 1.1.3. They go with 1.2's MCP work.
- Mnova's own zip (Save As > Script: NMReData): needs zip reading in three open routes. The user unzips first.
- 2D correlations, `NMREDATA_J`, DEPT, spectrum folders and JCAMP links: Octet has no model for them; named in the
  notice.
- Links on bonds: NMReDATA assigns atoms only, so a multiplet linked to a bond is not written.
- The WebKit look run of the panel with an imported list, and ChemDraw 22.2 opening our file: no app windows or
  ChemDraw runs in this task. Sam's real run covers them.
- A cap of 16 spectra across the whole drawing: the file's lists are capped at 16; the drawing had no cap before.
