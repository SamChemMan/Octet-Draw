## How

### The flag: `--into FILE`

```
octet --convert figures --to sdf --into compounds.sdf
```

- `--into FILE` goes with `--to sdf` (or `sdf2000`). Any other `--to`: refused, exit 2 ("--into goes with --to
  sdf."). With `--out`: refused ("--into names the new file, so it does not take --out."). `--each` with it is
  allowed and changes nothing.
- Each file is opened as `--each` opens it (hidden window, File > Open's limits, `--style` first). Each structure
  is one record from the same `read` call as `--each`. The data fields are `Number` (when it has one, as `--each`)
  and `File`.
- `File` is the file's path from the folder named on the command line, with `/` between folders
  (`inner/scheme2.cdx`), or its name when the file itself was named. Never the full path: a supporting-information
  file should not carry the user's folders.
- A data value is one line. A line break or other control character becomes a space. A value that starts with
  `$$$$` or `>` gets a space before it, so it never reads as the end of a record or the start of a field. This
  applies to `Number` with `--each` too (a number with a line break in it broke the record before).
- The records go into memory and are written once, at the end, with `write_atomic`, when at least one file gave
  records. The name follows `target()`: an existing file gets ` 2`, ` 3` unless `--overwrite`. Its extension is
  the one given (`.sd` stays `.sd`; none gives `.sdf`). Its folder is made if it is not there.
- Octet never reads the `--into` file or a numbered copy of it (`si.sdf`, `si 2.sdf`, same folder, same extension)
  as an input. Otherwise a second run over the same folder takes in the first run's compounds again.
- Output: one line a file (`scheme1.cdxml: 3 compounds`), then `Converted 2 of 2 files into compounds.sdf.` A file
  Octet cannot read is named on standard error and the exit code is 1, as now. If the SDF cannot be written, the
  error is named and the count is 0.

`--into` reads as "convert these, to SDF, into this file". The other names considered: `--combine` (needs a file
name anyway), `--one FILE` (unclear), and making `--out` take a file (changes what `--out` means).

### Code (`src-tauri/src/convert.rs`)

- `Job.into`, parsed and checked in `parse`.
- `files()` drops the `--into` file and its numbered copies (`written`).
- `source()` gives the `File` value. `record()` makes one SDF record from a MOL and its fields; `each()` uses it, so
  `--each`'s bytes are as before for every number with no control character in it.
- `run()`: with `--into`, collect the records and write once after the loop.

No change to `main.rs` (`--convert` already stays with AI off), the page, the MCP or `features.ts`.

## ChemDraw cross-check (from the notes only)

From `~/octet-research/notes/chemdraw26-inventory.md`, `chemdraw-inventory.md` and the 26.1 help text
(`help26/text`):

- ChemDraw has no command line or batch conversion. Its route for scripts is ChemScript (Python, from the
  Accessories toolbar, Windows command line), which the inventory lists as missing in Octet. Issue 91 itself says
  ChemDraw has no good answer here.
- ChemDraw's Save As writes SDF (V3000 by default since 23.0, V2000 listed apart). Octet's `--to sdf` and
  `--to sdf2000` match. "Expand Generic Structure to SDF" writes plain SDF of an enumeration; that is a query
  feature, not this.
- The notes record no data fields in ChemDraw's SDF export. Octet's `Number` and `File` fields are Octet's own, so
  there is no ChemDraw name to match. ChemNMR's help shows SDF data fields in the usual `> <NAME>` form, which
  Octet writes.

So Octet goes beyond ChemDraw here. Nothing ChemDraw offers is missing.

## Cut, and why

- No `--into` for other formats (one PDF of many drawings, one CDXML). The issue asks for one SDF only; a PDF of
  many pages is a separate feature.
- No other data fields (name, formula, SMILES, InChIKey). The issue asks for every compound; the `Number` and
  `File` fields let a reader match each record to the manuscript. More fields can follow if someone asks.
- Not run on Windows or Linux here. The CI steps are written for them and checked by `src/convert.check.ts`; the
  first run on GitHub proves them.
