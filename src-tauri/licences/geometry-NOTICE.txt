Rust geometry backend and parameter data
=======================================

Octet's 3D Optimise command uses its own Rust crate, octet-geometry
(src-tauri/geometry). It implements distance-geometry embedding, MMFF94,
MMFF94s, UFF, atom typing, energy/gradient evaluation and optimization in
plain Rust. Its public interface, worker protocol and worker-process design are
adapted from ReShiki (https://github.com/Ameyanagi/ReShiki), MIT OR Apache-2.0,
Copyright (c) 2026 Ameyanagi and ReShiki contributors. ReShiki's own geometry
backend, COSMolKit, is not used.

The crate follows the behaviour of RDKit (https://github.com/rdkit/rdkit), the
independent reference its tests compare with: atom typing, MMFF aromaticity
and charges, force-field terms and their empirical rules, and distance
geometry. It embeds RDKit's UFF and MMFF parameter tables as text files
(src-tauri/geometry/src/data), taken unchanged from the parameter strings of
RDKit 2026.09.2 (Code/ForceField/UFF/Params.cpp and
Code/ForceField/MMFF/Params.cpp). No C++ code, Python or RDKit runtime is
compiled, linked or needed: the application runs from its own executable.
Python with RDKit is used only by separate developer reference scripts.
